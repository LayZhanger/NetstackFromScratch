# 手搓网络协议栈 · 总体路线图

> 文档定位：本仓库的路线图。**本仓库范围 = 自研栈核心（netdev→链路层→网络层→UDP→QUIC）+ 基于自研 QUIC 的 HTTP/3 服务。**
> 配套视频：B站/抖音「Lay 的 RFC 实验室」同步更新（RFC 阅读方法论见该频道）。
> 范围外：QEMU/virtio、lwIP 对标、Linux 内核对标等，不在本仓库代码范围。
> 注：本仓库按功能/层组织，不设期数编号。

## 0. 传输层：QUIC

**本仓库传输层实现 QUIC（RFC 9000 系列），不实现 TCP（RFC 793）。**

说明：
- QUIC 跑在 **UDP** 之上（RFC 9000），UDP 阶段是 QUIC 的必要地基，顺序天然衔接。
- QUIC 承担传输层职责：可靠传输、流量控制、连接管理、多路复用（Streams）。
- 配套标准：RFC 9000（QUIC 核心）、RFC 9001（TLS 加密）、RFC 9002（丢包检测与拥塞控制）、RFC 9114（HTTP/3）。
- 里程碑与验证均为 QUIC 语义（连接建立/流/重传/关闭）。

## 1. 项目目标与原则

- **自底向上、分层递进**：netdev → 链路层 → 网络层 → UDP → QUIC → 应用层（HTTP）。
- **每步最小可运行**：一步只做一个可验证功能，做完立刻能抓包/单测验证。
- **每行代码可溯源 RFC**：核心结构体和关键函数逐行标注 RFC Section 编号。
- **抽象优先**：netdev 层屏蔽底层设备差异，协议栈只依赖接口，不依赖具体设备。
- **对照官方标准**：以 RFC 原文为准。

## 2. 阶段划分

| 阶段 | 范围 | 核心内容 |
|------|------|----------|
| 零 | 传输通道 | netdev：无协议裸收发，直接发到对端 |
| 一 | 链路层-以太网 | 以太网帧（MAC/EtherType/分流） |
| 二 | 链路层-ARP | 地址解析 + 缓存表 |
| 三 | 网络层 | IP + ICMP（里程碑1） |
| 四 | 传输层-UDP | UDP 收发 + 端口 + 校验和（RFC 768） |
| 五 | QUIC 基础 | QUIC 核心规范 + 包/帧封装（RFC 9000） |
| 六 | QUIC 连接 | 连接建立/关闭 + 连接 ID（RFC 9000/9001） |
| 七 | QUIC 可靠 | 序号/确认/丢包重传 + 流与流量控制（RFC 9000/9002） |
| 八 | 应用层 | 基于自研 QUIC 的 HTTP 服务（HTTP/3，RFC 9114，收官里程碑） |

## 4. 依赖关系

```
netdev(裸收发) ──→ 以太网 ──→ ARP ──→ IP ──→ ICMP(🔴里程碑1) ──→ UDP
                                                                     │
QUIC核心 ──→ QUIC包/帧 ──→ QUIC连接 ──→ 序号/确认/重传 ──→ 流/流控(🔴里程碑2)
                                                                     │
                                                         HTTP/3(🔴收官，基于自研 QUIC)
```

- 以太网依赖 netdev（以太网帧经 netdev 收发）
- ARP 依赖以太网（ARP 跑在以太网帧上）
- IP 依赖以太网 + ARP（IP 依赖 ARP 解析 MAC）
- ICMP 依赖 IP（ICMP 载荷由 IP 承载）
- UDP 依赖 IP（UDP 报文由 IP 承载）
- QUIC 依赖 UDP（QUIC 跑在 UDP 之上，RFC 9000）
- 连接建立依赖 QUIC 包/帧封装（握手是 QUIC 包序列）
- HTTP/3 依赖 QUIC 完成（HTTP/3 跑在自研 QUIC 之上）

## 5. 验证体系概述

两条验证通道，共用同一份协议栈代码：

| 通道 | 组成 | 用途 |
|------|------|------|
| **hub 自测** | sim 端口 + sim 端口（+ sim 端口） | 开发期逻辑正确性，确定性丢包/组播/多设备场景 |
| **hub + 真实内核** | sim 端口 + tap 端口 | 里程碑互操作验证：栈与 Linux 内核直接对话 |

里程碑期的「宿主机 ping」均通过 hub 的 tap 端口完成，不额外搭建环境。QUIC/HTTP 期验证：宿主机 QUIC 客户端/浏览器通过 hub 的 tap 端口访问自研栈服务。
