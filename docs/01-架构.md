# 手搓网络协议栈 · 总体架构设计

> 文档定位：定技术路线，所有代码都按这份设计写。本文件只写抽象与原则，具体实现细节按阶段补充。
> **传输层：实现 QUIC（RFC 9000 系列，跑在 UDP 之上），不实现 TCP（RFC 793）。**

## 1. 分层架构

```
┌─────────────────────────────────────────────┐
│ 应用层   apps/echo http（QUIC 完成后实现）  │
├─────────────────────────────────────────────┤
│ 传输层   quic/  udp/                        │  RFC 9000 / 768
├─────────────────────────────────────────────┤
│ 网络层   ip/   icmp/                         │  RFC 791 / 792
├─────────────────────────────────────────────┤
│ 链路层   eth/  arp/                          │  RFC 894 / 826
├─────────────────────────────────────────────┤
│ netdev   抽象接口：hub 端口（单缓冲收发）      │
└─────────────────────────────────────────────┘
```

### 职责边界

| 层 | 管什么 | 不管什么 |
|----|--------|----------|
| netdev | 整帧搬运（收发完整帧字节） | 帧内格式、地址、分流 |
| eth | 以太网帧格式：拆/拼帧头、EtherType 分流（IP/ARP/组播识别） | 底层设备差异 |
| arp | MAC 地址解析、缓存表、广播请求/单播应答 | 以太网帧封装 |
| ip | IP 首部、校验和、收发路由 | 帧格式、链路差异 |
| udp | 端口、UDP 报文封装、校验和 | 可靠性、连接管理 |
| quic | 连接/流/帧、可靠传输、流量控制、加密 | 网络层封装、链路差异 |

**核心约定**：netdev 负责"运输"，eth 负责"格式"，职责不重叠。

## 2. 运行时模型：单缓冲 + 事件驱动主循环

- 全局单包缓冲区：一坨字节从 netdev 进来，各层在其上原地解析/封装，不复制、无 malloc。
- 连接表为静态数组（连接数编译期定），无动态内存。
- 事件驱动：数据到达 / 周期定时器 触发处理。

### 主循环伪代码

```
loop:
    len = netdev_read()
    if len > 0:
        链路层处理 → 网络层分流 → 传输层/应用层
        若有回包: netdev_send()
    elif periodic_timer_expired():
        netdev_periodic()   # QUIC 丢包重传/定时器、ARP 缓存老化
```

- `netdev_read` 一次收一个完整帧；`netdev_send` 一次发一个完整帧。
- 周期定时器单独驱动，与收包互不干扰。

## 3. netdev 抽象层

### 定位

netdev 是协议栈与底层收发设备之间的抽象接口，**无任何协议语义**：不做地址、不做格式、不做分流，只负责把收到的字节直接交给上层、把上层的字节直接发到对端。协议栈只依赖接口，不依赖任何具体设备。**具体实现方式本文件不展开，按阶段确定。**

> 实现顺序：netdev 是第一步实现的功能（无协议裸收发），以太网、ARP 在其上各自独立实现。

### 接口

```c
struct netdev_ops {
    int      (*init)(struct netdev *);
    ssize_t  (*read)(struct netdev *, uint8_t *buf, size_t buflen);   // 收一帧
    int      (*send)(struct netdev *, const uint8_t *buf, size_t len); // 发一帧
    void     (*periodic)(struct netdev *);                            // 周期定时器
};
```

### 为什么要抽象

- **换设备不重写协议栈**：后面换硬件只需新增一个后端，链路层以上一行不改。
- **测试可插可控链路**：能插入丢包/延迟/组播订阅等行为，验证确定性场景。

## 4. 虚拟局域网（hub）

### 形态

多设备仿真，每台设备 = 一个 C 协议栈进程。所有设备通过 hub（虚拟交换机）互连。**其中一个设备是宿主机 Linux：hub 内置 TAP 设备（tap0），把帧写进 tap0 即发给 Linux 内核，Linux 内核发出的帧也从 tap0 进入 hub。**

```
            hub（虚拟交换机，仅 L2）
    ┌───────────┼───────────┐
  端口0       端口1        端口2
   │           │           │
 Linux 内核   自研栈A      自研栈B
 (tap0)      (进程A)      (进程B)
```

- 端口0 = **tap 端口**：hub 自身打开 `/dev/net/tun` 建 tap0，与宿主机 Linux 内核 TCP/IP 栈对话（真实栈，验证 RFC 合规性，非"自己测自己"）。
- 端口1/2 = **sim 端口**：自研 C 协议栈进程通过 fd 连 hub，每进程一实例。
- 每台设备互不感知，只和 hub 通信；hub 是整个局域网的共享介质，可见局域网内所有帧。
- 三种端口转发规则一视同仁：广播/组播/单播对 tap 端口同样生效。

### 转发规则

| 帧类型 | 判断依据 | hub 行为 |
|--------|----------|----------|
| 广播 | 目的 MAC = `FF:FF:FF:FF:FF:FF` | 发给除源之外所有端口 |
| 组播 | 目的 MAC 首字节 I/G 位 = 1 | 查订阅表 → 只发订阅端口 |
| 单播 | 其余 | 查 MAC 学习表 → 只发对应端口；未知洪泛 |

### hub 能力

- 按端口配置丢包/延迟（确定性测试用）。
- 抓包日志 + 可导出 pcap 给 Wireshark（局域网全景视角）。
- 组播订阅登记：设备向 hub 声明加入某组播 MAC。

### 与真实内核的互操作

端口0（tap 端口，tap0）即与 Linux 内核 TCP/IP 栈对话，验证 RFC 合规性（非"自己测自己"），详见上方「形态」。里程碑期的「宿主机 ping」、QUIC/HTTP 访问均经此端口完成。

## 5. 链路层组播（第一阶段交付）

- **识别**：以太网帧目的 MAC 首字节最低位（I/G 位）= 1 即为组播帧。
- **hub 转发**：按订阅表把组播帧只发到订阅端口。
- **栈侧过滤**：eth 层识别组播帧，仅已订阅的组向上层递交。
- **RFC 1112 映射函数**：IP 组播地址 → 组播 MAC（`224.x.x.x` → `01:00:5E:00:00:00 | 低23位`），本阶段先提供函数，IP 层使用后续再接入。

> 边界：本阶段只做链路层组播，不实现 IGMP、不做 IP 组播路由。

## 6. 关键设计取舍

| 取舍 | 选择 | 理由 |
|------|------|------|
| 缓冲模型 | 单缓冲原地复用 | 教学清晰、嵌入式友好，无 malloc |
| 连接管理 | 静态数组 | 数量固定，避免动态内存复杂性 |
| 设备抽象 | netdev 接口 | 换设备/测试可控 |
| 多设备 | 多进程 + hub | 每进程单实例栈，实现简单、演示直观 |
| UDP | 正式实现（RFC 768） | QUIC 跑在 UDP 之上，UDP 是 QUIC 的必要地基；先于 QUIC 完成 |
| 传输层 | QUIC（RFC 9000 系列） | 不实现 TCP；QUIC 承载可靠传输/流控/连接/多路复用 |
| 参考实现 | 借鉴 uIP/lwIP 的架构思路 | 代码全部自研，不复制 |

## 7. UDP 实现

- 位置：传输层底层，QUIC 跑在 UDP 之上（RFC 9000），UDP 是 QUIC 的必要地基（RFC 768）。
- 内容：`udp_in/udp_out`、端口表（静态数组）、UDP 校验和。
- 校验和：IPv4 中可选但予以实现。
- 验证：Wireshark 识别合法 UDP 报文；hub 上两台设备互发 UDP。

## 8. QUIC 实现

- 位置：传输层，跑在 UDP 之上（RFC 9000 系列）。
- 内容：
  - QUIC 包格式（长/短头）与帧类型（RFC 9000 §12-19）
  - 连接建立/关闭 + 连接 ID（RFC 9000 §5/§7/§10）
  - 序号、ACK、丢包检测与重传（RFC 9000 §13 + RFC 9002）
  - 流（Streams）多路复用 + 流/连接级流量控制（RFC 9000 §2-4）
  - 加密：TLS 集成（RFC 9001），按最小可用范围实现
- 验证：Wireshark 识别合法 QUIC 包；hub 双设备 QUIC 连接建立、多流传输、模拟丢包自动重传。

## 9. 应用层：HTTP 服务

- 运行在本仓库自研 QUIC 之上（HTTP/3，对照 RFC 9114）。
- 服务能力：监听固定端口，接收请求、返回网页内容。
- 边界：最小实现，不做并发/超时/多虚拟主机等工业级特性（教学主线仍以协议栈核心为准）。

## 10. 演进路径

```
netdev → 链路层(eth/arp) → 网络层(ip/icmp) → 传输层(udp → quic) → 应用层(http)
```

每层完成后立即通过 hub 验证，QUIC 完成后实现 HTTP 收官。本仓库不涉及 QEMU/virtio、lwIP、Linux 内核等范围外内容。
