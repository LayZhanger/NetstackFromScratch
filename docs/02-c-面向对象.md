# C 面向对象编码机制（ops 表多态）

> 文档定位：讲解本仓库的 C 面向对象编码机制（ops 表多态）。本文件负责讲清楚机制与原理，可运行佐证见 `tests/unit/test_ops.c`。

## 1. 为什么用 C 面向对象

协议栈要支持**换后端不重写协议栈**：hub 端口、tap、未来可能的硬件网卡，对上层暴露同一套收发接口。用 C 的 struct + 函数指针表（ops 表）实现多态：

- **换设备只新增一个后端**，链路层以上一行不改（架构文档 §3 netdev 抽象层的核心动机）。
- **无 malloc、无虚表运行时修改**：ops 表编译期静态初始化，实例用全局静态变量或编译期静态数组。
- **教学清晰**：每个机制都能在 `tests/unit/test_ops.c` 里单独验证。

## 2. 核心机制速查表

| C++ 概念 | 内核风格 C 实现 | 参照 |
|----------|----------------|------|
| 类 | `struct xxx`（数据成员）+ `struct xxx_ops`（方法表） | `net_device`、`net_device_ops` |
| 虚函数/多态 | ops 表函数指针，C99 指定初始化静态表 | `file_operations` |
| 方法调用 | `self->ops->method(self, args)` | 内核惯例 |
| 继承 | 子结构内嵌基结构（**首成员**），向上转型即强转基指针 | `sock_common` |
| this | 方法首参 `self`，类型为所属 struct 指针 | — |
| 构造 | `xxx_init(struct xxx *self, ...)` 就地初始化，无 malloc/free | `netif_add` |
| 泛型容器操作 | `container_of` 反推包含结构 | 内核 container_of |

## 3. 类模板

### 3.1 基类：`src/netdev/netdev.h`（形态）

```c
struct netdev {
    const struct netdev_ops *ops;   /* 虚表，约定放首成员 */
    uint8_t *rx_buf;                /* 指向全局单包缓冲区 */
    size_t   rx_buflen;
};

struct netdev_ops {                 /* 全部虚方法，self 首参 */
    int      (*init)(struct netdev *self);
    ssize_t  (*read)(struct netdev *self, uint8_t *buf, size_t buflen);
    int      (*send)(struct netdev *self, const uint8_t *buf, size_t len);
    void     (*periodic)(struct netdev *self);
};
```

**为什么 ops 放首成员**：一是向上转型后 `(struct netdev *)&子类` 直接可用（首成员偏移为 0，强转无风险）；二是 `container_of` 反推时以 `base` 成员偏移 0 简化计算。

### 3.2 子类：继承 + 私有数据 + 实现 + 注册

```c
struct hubport_netdev {
    struct netdev base;             /* 继承：首成员内嵌基结构 */
    int fd;                         /* 子类私有数据 */
};

/* 虚方法实现（static，不导出） */
static int hubport_init(struct netdev *self)
{
    if (self->ops != &hubport_ops)  /* 校验 self：分派必须传回实例本身 */
        return -1;
    self->name = "hubport";
    return 0;
}

static ssize_t hubport_read(struct netdev *self, uint8_t *buf, size_t buflen)
{
    struct hubport_netdev *hp = container_of(self, struct hubport_netdev, base);
    ...
}

/* 指定初始化绑定虚表（必须 static const） */
static const struct netdev_ops hubport_ops = {
    .init     = hubport_init,
    .read     = hubport_read,
    .send     = hubport_send,
    .periodic = hubport_periodic,
};

/* 构造：就地初始化静态实例 */
static struct hubport_netdev hp_netdev;

void hubport_netdev_init(struct hubport_netdev *hp)
{
    hp->base.ops = &hubport_ops;    /* 绑定虚表 */
    ...
}
```

### 3.3 使用（多态调用）

```c
struct netdev *nd = (struct netdev *)&hp;   /* 向上转型 */
int ret = nd->ops->send(nd, rx_buf, len);   /* 动态分派到子类实现 */
```

### 3.4 多态分派原理

`nd->ops->send(nd, ...)` 实际执行的是 `ops` 指针指向的那张表里的函数。`nd` 指向哪个实例，实例首成员 `ops` 就指向哪张表（哪个后端），从而分派到对应实现。这就是"结构体=类、ops 表=虚表"的完整机制，与 C++ 虚表同构，只是手动管理。

## 4. container_of 反推

### 4.1 何时需要

回调（如收包处理）只拿到 `struct netdev *` 基指针，但实现内部需要子类私有的 `fd`：

```c
struct hubport_netdev *hp = container_of(nd, struct hubport_netdev, base);
```

### 4.2 原理

```c
#define container_of(ptr, type, member) \
    ((type *)((char *)(ptr) - (char *)&((type *)0)->member))
```

- `(char *)&((type *)0)->member`：计算 `member` 在 `type` 内的**偏移量**。
- 用 `ptr`（指向成员的实际地址）减去偏移量 = 外层结构起始地址。

**特例**：`base` 是首成员时偏移为 0，`container_of` 退化为直接强转。但统一用宏更健壮——成员挪位后代码不用改。

### 4.3 为什么不直接强转

`(struct hubport_netdev *)nd` 在这个场景结果相同，但**强转掩盖了"反推"的语义**：基指针来源可能是任意子类（hubport / loopback / tap），强转编译器不检查类型关系，容易写错。`container_of` 明确表达"我知道这个成员在哪个结构里，我要拿整个结构"。

## 5. 生命周期与约束（无 malloc）

| 阶段 | 函数 | 要求 |
|------|------|------|
| 构造 | `xxx_init(struct xxx *self, ...)` | 每个类必有；就地初始化静态实例/数组元素；绑定 ops 表；失败返回负值 |
| 复位 | `xxx_reset(struct xxx *self)` | 可选；把实例复位到初始态（重连、连接复用场景） |
| 销毁 | 无 | 无 malloc 故无 free；进程退出即销毁 |

- 实例来源：**全局静态单例**（如 netdev）或**编译期静态数组**（连接表、端口表，数量由宏定）。
- 禁止：裸用未 init 的实例；初始化时 malloc/free；实例化数量运行时可变。
- 返回约定：`0 = 成功`，负 = 失败（`-1` 或 `-EINVAL` 风格负数），收包类用 `ssize_t` 返回长度，负 = 错误。
- **先 init 后使用是硬约束**：test_ops 开发期踩过的坑——栈实例未 memset 清零，`rx_bytes` 读出来是垃圾值（test_container_of 首次跑出 2 而非 1）。测试里对栈实例显式 memset，模拟"初始化"语义。
